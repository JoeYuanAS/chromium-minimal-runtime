# 已改与未改清单

本文记录当前 MVP 阶段已经做过的改动、没有改的部分、以及后续应该继续裁剪的位置。

## 一、已经改的内容

### 1. 源码获取方式

已经从“下载官方 content-shell 二进制”转向“最小历史源码 checkout”：

- 使用 `git clone --depth=1`，不保留完整提交历史。
- 使用 `--filter=blob:none`，按需拉 blob。
- 使用 `sparse-checkout` 起步展开部分目录。

相关脚本：

```text
/Users/zy.yuan/Develop/browser-runtime-projects/chromium-minimal-runtime/scripts/fetch_chromium_sparse_source.sh
```

### 2. Chromium GN 根配置

在 Chromium 源码树中增加了最小化开关：

```text
/Users/zy.yuan/Develop/browser-runtime-projects/chromium-workspace/src/build/config/content_shell_minimal.gni
```

并在：

```text
/Users/zy.yuan/Develop/browser-runtime-projects/chromium-workspace/src/build/config/BUILD.gn
```

引入 `content_shell_minimal.gni`，给编译单元注入：

```text
CONTENT_SHELL_MINIMAL_ROOT=1
```

这个宏用于让源码里可以根据 MVP 最小运行时进行条件编译。

### 3. GN args 裁剪

已经通过 `out/ContentShell/args.gn` 关闭了一批非 MVP 能力：

- debug 符号：`symbol_level = 0`、`blink_symbol_level = 0`、`v8_symbol_level = 0`
- PDF：`enable_pdf = false`
- 打印：`enable_printing = false`
- 扩展：`enable_extensions = false`
- Guest view：`enable_guest_view = false`
- Safe Browsing：`safe_browsing_mode = 0`
- Remoting：`enable_remoting = false`
- Media remoting：`enable_media_remoting = false`
- 多种媒体编解码：`media_use_ffmpeg = false`、`media_use_libvpx = false`、`enable_av1_decoder = false`
- 企业策略能力：多项 `enterprise_* = false`
- Accessibility service：`enable_accessibility_service = false`
- Screen AI：`enable_screen_ai_service = false`
- On-device translation/model：`enable_on_device_translation = false`、`use_on_device_model_service = false`
- WebNN 后端：`webnn_use_tflite = false`、`webnn_use_litert = false`、`webnn_use_chrome_ml_api = false`
- ANGLE/Vulkan/Dawn 的部分后端：`angle_enable_vulkan = false`、`dawn_enable_vulkan = false`

### 4. Chrome 产品层依赖规避

当前 Chromium 源码中有一批 GN 和 C++ 改动，目标是让 `content_shell` 编译时少碰 Chrome 产品层、Signin、Sync、Enterprise、WebUI 等依赖。

涉及方向包括：

- `chrome/browser/buildflags.gni` 导入问题规避。
- `signin` / `sync` / `trusted_vault` 相关依赖裁剪。
- `enterprise` 相关 GN target 关闭或弱化。
- `optimization_guide`、on-device model、translation 相关依赖裁剪。
- `webnn` 相关服务和 Blink 入口裁剪。
- `webauthn` / passkey sync 相关依赖裁剪。
- `content` 内部 WebUI 资源裁剪。
- SODA / speech / screen AI 相关依赖裁剪。
- IWA 相关入口裁剪。

当前 Chromium 源码树中 `git status --short` 显示改动范围较大，主要集中在：

- `BUILD.gn`
- `build/config/BUILD.gn`
- `components/**/BUILD.gn`
- `content/browser/**`
- `content/shell/**`
- `content/utility/**`
- `media/**`
- `services/**`
- `third_party/blink/**`
- `ui/**`
- `skia/**`

这些改动目前还没有整理成独立 patch series，也没有形成可重复应用的补丁目录。

### 5. Blink / Skia / 图片路径修补

为减少特定 Rust image codec 或测试依赖带来的编译问题，做过以下方向的调整：

- PNG/BMP 相关路径倾向使用 C++/libpng 路径。
- 部分 Blink image encoder/decoder 依赖做了最小化处理。
- `third_party/libpng/visibility.gni` 有相关可见性调整。

这些改动属于编译闭环修补，还没有证明是最终最优裁剪方案。

### 6. Fake geolocation 恢复

为了让 `content_shell` 在当前形态下可运行，恢复了 fake geolocation 相关依赖。

副作用：

- 当前仍然可能通过 `//services/device/public/cpp:test_support` 拉入 gtest/gmock 和一批测试支撑文件。
- 这是后续应重点优化的体积来源之一。

### 7. output app 可启动性修补

当前 `output/content-shell-minimal/Content Shell.app` 不是简单从 `out/ContentShell` 复制出来的原样 app，而是做了可启动性修补：

- 补入 `libtest_trace_processor.dylib`。
- 对 app bundle 做 ad-hoc 签名。
- 增加 Mach-O launcher：

```text
/Users/zy.yuan/Develop/browser-runtime-projects/chromium-minimal-runtime/src/content_shell_app_launcher.c
```

launcher 负责把真实二进制启动为：

```text
Contents/MacOS/Content Shell.bin --log-file=/tmp/content_shell.log
```

避免 `content_shell.log` 写入 app bundle 内部破坏签名。

## 二、没有改的内容

### 1. 还没有做完整的源码级最小化

当前已经能编译和启动，但还不是“源码层真正最小集”。

原因：

- Chromium 的 GN 依赖图很大。
- 目前很多地方是为了让 `content_shell` 编译通过而做条件裁剪。
- 部分依赖只是从打包阶段删掉，或在 output app 阶段补齐，并没有从源码根上消除。

### 2. 还没有移除 `libtest_trace_processor.dylib`

当前 framework 明确依赖：

```text
@loader_path/Libraries/libtest_trace_processor.dylib
```

所以提取版必须带：

```text
Contents/Frameworks/Content Shell Framework.framework/Versions/C/Libraries/libtest_trace_processor.dylib
```

这是一个临时状态。后续应该继续查是谁把 test trace processor 链进 `Content Shell Framework`，从 GN target 层消掉它。

### 3. 还没有去掉 fake geolocation 带来的测试支撑依赖

当前为了启动稳定，保留了 fake geolocation 相关支持。

后续更好的做法：

- 写一个只满足 content_shell 运行需要的极小 geolocation fake target。
- 避免继续依赖 `//services/device/public/cpp:test_support`。
- 避免 gtest/gmock 进入运行时依赖图。

### 4. 还没有把提取流程脚本化

当前 `output/content-shell-minimal/Content Shell.app` 已经手工修到可启动，但还没有正式脚本把下面流程串起来：

1. 从 `out/ContentShell/Content Shell.app` 提取必要文件。
2. 用 `otool -L` 递归计算 `@loader_path` / `@executable_path` dylib 依赖闭包。
3. 复制必要 Resources、Helpers、Libraries。
4. 编译并注入 launcher。
5. ad-hoc codesign。
6. 启动 smoke test。
7. 验证运行后 bundle 签名仍有效。

这是下一步应该补的工程化脚本，否则每次编译后容易再次漏文件。

### 5. 还没有做自动化 smoke test

当前验证主要是手工命令：

```bash
open -n ".../Content Shell.app" --args 'data:text/html,<html><body>open-launcher-ok</body></html>'
codesign --verify --verbose=6 ".../Content Shell.app"
```

还没有把它变成 CI 或本地一键测试脚本。

建议后续增加：

- 启动 app。
- 检查进程是否出现。
- 检查 DevTools listening。
- 终止进程。
- 检查 `codesign --verify` 仍然通过。
- 检查 bundle 内没有新增 `content_shell.log`。

### 6. 还没有实现采集 API

项目 README 里提到的目标 API 还没有真正落地：

- `goto`
- `click`
- `input`
- `wait`
- `evaluate`
- `extract`
- `screenshot`

当前只是让最小化 `content_shell` 能编译、能启动，还没有形成可供业务调用的 automation runtime。

### 7. 还没有做反爬相关能力

当前没有系统性修改：

- Navigator 指纹。
- Canvas 指纹。
- WebGL 指纹。
- Audio 指纹。
- Timezone / Language / Screen。
- TLS / HTTP2 指纹。
- 有头/无头一致性细节。

也就是说，当前解决的是“源码裁剪与运行时体积”的第一步，不是完整反爬运行时。

### 8. 还没有做 macOS 发布签名

当前签名方式是：

```bash
codesign --force --deep --sign - Content Shell.app
```

这只是本地 ad-hoc 签名。

还没有做：

- Developer ID 签名。
- Hardened Runtime 配置。
- Notarization。
- DMG/PKG 分发。

## 四、下一步建议

优先级从高到低：

1. 写 `scripts/package_content_shell_minimal.sh`，把提取、依赖闭包、launcher、签名、smoke test 全部脚本化。
2. 从 GN 依赖图里移除 `libtest_trace_processor.dylib`。
3. 替换 fake geolocation 的测试支撑依赖，避免 gtest/gmock 进入运行时。
4. 把当前 Chromium 改动整理成 patch series 或 `patches/` 目录。
5. 再做一轮体积分析，按 framework 符号和 GN target 找最大依赖源。
6. 开始做 automation API 和有头/无头一致性验证。
